## EXECUTIVE SUMMARY

To develop a genuinely knowledgeable, context-aware cybersecurity assistant rather than a generic prompt-engineered LLM, SENTINEL AI has conducted an in-depth empirical audit of five foundational cybersecurity data resources:

1. **Dataset 1:** Canadian Institute for Cybersecurity — **CIC-IDS2017** (Network Traffic Intrusion Detection Dataset)
2. **Dataset 2:** Kaggle / Hugging Face — **Phishing Email & Malicious URL Dataset**
3. **Dataset 3:** Los Alamos National Laboratory (LANL) — **Comprehensive Multi-Source Cyber-Security Events (cyber1)**

5. **GitHub Repository:** LogPAI — **`logpai/loghub`** (System Log Datasets & Log Analytics Framework)

This document provides a rigorous, individual analysis of each resource, covering schemas, scale, feature distributions, data quality anomalies, and exact suitability across RAG, Supervised Fine-Tuning, Structured Cybersecurity Analysis, and Evaluation.

## 1. RESOURCE 1: CIC-IDS2017 (CANADIAN INSTITUTE FOR CYBERSECURITY)

### 1.1 Dataset Name & Source
- **Name:** CIC-IDS2017 (Intrusion Detection Evaluation Dataset)
- **Source:** Canadian Institute for Cybersecurity (CIC), University of New Brunswick (Iman Sharafaldin, Arash Habibi Lashkari, Ali A. Ghorbani, 2018).
- **Hosting:** Primary hosting via UNB CIC, mirrored extensively across Kaggle (`cicids2017`) and Hugging Face.

### 1.2 Description
CIC-IDS2017 represents a realistic benign background traffic profile interwoven with contemporary, multi-vector cyberattacks captured over five continuous business days (Monday July 3, 2017 through Friday July 7, 2017). Network traffic was captured via a B-Profile system generating natural human background traffic (HTTP, HTTPS, FTP, SSH, Email) alongside executed adversarial toolkits.

### 1.3 File Formats & Scale
- **File Formats:** Raw PCAP files (51.3 GB) and bi-directional network flow CSV files extracted via CICFlowMeter.
- **Total Records:** 2,830,743 network flow rows across 8 CSV files.
- **Time Window:** 5 days (Monday to Friday, 8:00 AM to 5:00 PM daily).

### 1.4 Available Columns & Features (79+ Extracted Features)
The flow features generated by `CICFlowMeter` capture temporal, volumetric, and statistical packet dynamics:
- **Network Identifiers:** `Destination Port`, `Flow Duration`.
- **Volumetric Metrics:** `Total Fwd Packets`, `Total Backward Packets`, `Total Length of Fwd Packets`, `Total Length of Bwd Packets`, `Flow Bytes/s`, `Flow Packets/s`.
- **Packet Length Distribution:** `Fwd/Bwd Packet Length Max/Min/Mean/Std`, `Min/Max Packet Length`, `Packet Length Mean/Std/Variance`, `Average Packet Size`.
- **Inter-Arrival Time (IAT):** `Flow IAT Mean/Std/Max/Min`, `Fwd/Bwd IAT Total/Mean/Std/Max/Min`.
- **TCP Control Flags:** `FIN Flag Count`, `SYN Flag Count`, `RST Flag Count`, `PSH Flag Count`, `ACK Flag Count`, `URG Flag Count`, `CWE Flag Count`, `ECE Flag Count`.
- **Window & Segment Sizing:** `Init_Win_bytes_forward`, `Init_Win_bytes_backward`, `min_seg_size_forward`, `act_data_pkt_fwd`.
- **Traffic Bursts & Subflows:** `Subflow Fwd/Bwd Packets/Bytes`, `Active Mean/Std/Max/Min`, `Idle Mean/Std/Max/Min`.
- **Target Variable:** `Label` (Categorical string).

### 1.5 Labels & Class Distribution
The dataset contains 15 categorical classes:
- `BENIGN`: 2,273,097 (80.3%)
- `DoS / DDoS Attack Variants`:
  - `DoS Hulk`: 231,073 (8.16%)
  - `PortScan`: 158,930 (5.61%)
  - `DDoS`: 128,027 (4.52%)
  - `DoS GoldenEye`: 10,293 (0.36%)
  - `DoS slowloris`: 5,796 (0.20%)
  - `DoS Slowhttptest`: 5,499 (0.19%)
- `Brute-Force Authentication`:
  - `SSH-Patator`: 5,897 (0.21%)
  - `FTP-Patator`: 7,938 (0.28%)
- `Web Attacks`:
  - `Web Attack - Brute Force`: 1,507 (0.05%)
  - `Web Attack - XSS`: 652 (0.02%)
  - `Web Attack - Sql Injection`: 21 (0.0007%)
- `Infiltration & Botnets`:
  - `Bot`: 1,966 (0.07%)
  - `Infiltration`: 36 (0.001%)
  - `Heartbleed`: 11 (0.0004%)

### 1.6 Data Quality Issues, Missing Values & Duplicates
- **Infinite / NaN Values:** `Flow Bytes/s` and `Flow Packets/s` produce `Infinity` and `NaN` when `Flow Duration == 0`. These require programmatic sanitization (clamping to max finite float or dropping).
- **Duplicate Records:** Approximately 308,381 duplicate flow records exist due to overlapping sniffing sensors.
- **Class Imbalance:** Extreme skew (Benign constitutes >80%, while Heartbleed and SQLi have <25 samples), making naive cross-entropy training ineffective.

### 1.7 Cybersecurity Value & SENTINEL AI Suitability
- **RAG Suitability:** High for MITRE ATT&CK mapping (e.g. T1498 DoS, T1110 SSH-Patator, T1046 PortScan, T1190 Exploit Public-Facing App).
- **Structured Analysis Suitability:** **Exceptional.** Perfect for deterministic flow velocity checks, threshold detection, and feature correlation tools.
- **Supervised Fine-Tuning:** Unsuitable for direct LLM weight tuning (numerical tabular data degrades LLM linguistic capability), but ideal for lightweight ML classification models (XGBoost, Random Forest).
- **Evaluation:** Ideal benchmark for evaluating whether SENTINEL AI correctly distinguishes between normal high-throughput HTTPS flows and asymmetric low-and-slow attacks (e.g. Slowloris).

## 2. RESOURCE 2: PHISHING EMAIL & MALICIOUS URL DATASET

### 2.1 Dataset Name & Source
- **Name:** Phishing Email & Malicious URL Benchmark Collection
- **Source:** Kaggle (Kaggle Phishing Email Dataset, Mendeley Data, and Hugging Face `ealvaradob/phishing-dataset`).
- **Curators:** Cybersecurity threat intelligence researchers compiling corporate gateway captures, SpamAssassin corpuses, PhishTank, and OpenPhish feeds.

### 2.2 Description
A curated corpus of raw email headers, message bodies, embedded URLs, and authentication verification outcomes (SPF, DKIM, DMARC), accompanied by extracted lexical features designed to detect credential harvesting, executive impersonation (BEC), and malicious link injection.

### 2.3 File Formats & Scale
- **File Formats:** CSV, JSON, and raw RFC 822 `.eml` files.
- **Total Records:** 82,486 labeled emails (48,210 legitimate, 34,276 phishing/scam).
- **URL Subcorpus:** 450,000 labeled URLs (benign, phishing, malware, defacement).

### 2.4 Available Columns & Features
- **Header & Provenance:** `email_id`, `sender` (RFC 5322 From), `return_path`, `reply_to`, `recipient`.
- **Content & Structure:** `subject`, `body_text`, `body_length`, `html_tags_count`, `script_tags_count`.
- **Link & Attachment Features:** `num_links`, `has_ip_in_url`, `num_subdomains`, `suspicious_tld_flag`, `attachments_count`, `has_executable_attachment`.
- **Authentication Indicators:** `spf_result` (PASS, FAIL, SOFTFAIL, NONE), `dkim_result` (PASS, FAIL), `dmarc_result`.
- **Behavioral Indicators:** `urgency_keywords_count` (e.g., *urgent, suspended, immediately, 24 hours*), `target_brand` (e.g., *PayPal, Microsoft, AWS, Workday*).
- **Target Variable:** `label` (`phishing` vs `legitimate`).

### 2.5 Class Distribution & Data Quality
- **Distribution:** Balanced (~58% legitimate, ~42% phishing).
- **Missing Values:** Incomplete headers in legacy corpus samples; missing SPF/DKIM tags in older webmail extracts.
- **Duplicates:** Near-duplicate email templates where only the embedded URL or victim email was mutated.

### 2.6 Cybersecurity Value & SENTINEL AI Suitability
- **RAG Suitability:** **Very High.** Provides structured linguistic threat intelligence on phishing tactics, social engineering indicators, and sender spoofing mechanisms.
- **Structured Analysis Suitability:** **High.** Enables real-time email header inspection tools in SENTINEL AI, detecting brand mismatch, IP-in-URL, and SPF failure.
- **Supervised Fine-Tuning:** Highly suitable for instruction-tuning an LLM to explain why an email is malicious and extract IOCs.
- **Evaluation:** Benchmark for validating SENTINEL AI's zero-hallucination analysis of email lures.

## 3. RESOURCE 3: LANL COMPREHENSIVE MULTI-SOURCE CYBER-SECURITY EVENTS (CYBER1)

### 3.1 Dataset Name & Source
- **Name:** Comprehensive, Multi-Source Cyber-Security Events (`cyber1`)
- **Source:** Los Alamos National Laboratory (LANL), Advanced Research in Cyber Systems (A-4) Group (Alexander D. Kent, 2015).
- **Identifier:** DOI `10.17021/1179829`.
- **URL:** `https://csr.lanl.gov/data/cyber1/`

### 3.2 Description
A massive enterprise-scale security dataset recording 58 consecutive days of continuous, de-identified event telemetry collected across LANL's internal corporate network. It represents one of the largest public ground-truth cybersecurity benchmarks in existence, capturing interactions between 12,425 enterprise users, 17,684 host computers, and 62,974 individual processes.

Crucially, the dataset includes an authentic, documented **Red Team penetration exercise** that occurred during the 58-day window, providing verifiable ground-truth compromise milestones.

### 3.3 File Formats & Scale
- **Format:** Gzip-compressed comma-separated values (`.txt.gz`).
- **Compressed Size:** ~12 GB (Uncompressed: >100 GB).
- **Total Record Count:** **1,648,275,307 events** (1.64 billion rows).
- **Individual File Composition:**
  1. `auth.txt.gz` (7.2 GB compressed): Windows Active Directory and endpoint authentication logs.
  2. `proc.txt.gz` (2.2 GB compressed): Windows process creation and termination telemetry.
  3. `flows.txt.gz` (1.1 GB compressed): Central router Netflow traffic.
  4. `dns.txt.gz` (177 MB compressed): Internal DNS server lookup queries.
  5. `redteam.txt.gz` (4.8 KB compressed): Validated Red Team compromise ground truth (749 events).

### 3.4 Schemas & Column Breakdown

#### A. Authentication Events (`auth.txt.gz`)
`time, source_user@domain, destination_user@domain, source_computer, destination_computer, auth_type, logon_type, auth_orientation, outcome`
- `time`: Integer seconds from epoch 1 to day 58.
- `source_user@domain`: Anonymized initiating user (e.g. `U748@DOM1`) or system principal (`SYSTEM@C625`).
- `destination_user@domain`: Target credential principal.
- `source_computer` / `destination_computer`: Anonymized host identifiers (e.g. `C17693`, `C728`).
- `auth_type`: `Negotiate`, `Kerberos`, `NTLM`, `?`.
- `logon_type`: `Interactive`, `Network`, `Batch`, `Service`, `Unlock`, `RemoteInteractive`.
- `auth_orientation`: `LogOn`, `LogOff`, `TGS` (Kerberos Ticket Granting Service), `TGT`.
- `outcome`: `Success` or `Fail`.

#### B. Process Execution (`proc.txt.gz`)
`time, user@domain, computer, process_name, action`
- `process_name`: Anonymized process token (`P16`, `P25`) with execution state (`Start`, `End`).

#### C. Network Flows (`flows.txt.gz`)
`time, duration, source_computer, source_port, destination_computer, destination_port, protocol, packet_count, byte_count`
- Preserves well-known destination ports (e.g. 80, 443, 53, 88, 389).

#### D. DNS Lookups (`dns.txt.gz`)
`time, source_computer, computer_resolved`

#### E. Ground Truth Red Team (`redteam.txt.gz`)
`time, user@domain, source_computer, destination_computer`
- 749 verified adversarial compromise entries documenting credential reuse and lateral movement across systems (e.g. from jump box `C17693` to targets `C728`, `C1173`, `C294`).

### 3.5 Class Distribution & Data Quality
- **Adversary Events:** 749 red team compromise actions against 1.64 billion total events (a needle in an immense haystack: $\approx 0.000045\%$).
- **Consistency:** High fidelity; user `U1` and computer `C1` remain consistent across all 5 files.
- **Missing Data:** Unobserved fields represented by `?`.
- **Anonymization Impact:** Names of executable binaries and actual IP subnets are masked, requiring the model to reason about structural graph topology, lateral hops, and temporal velocity rather than static file signatures.

### 3.6 Cybersecurity Value & SENTINEL AI Suitability
- **RAG Suitability:** High for domain understanding of Active Directory Kerberos/NTLM authentication flows, lateral movement (MITRE T1021.002, T1078), and Red Team behavior.
- **Structured Analysis Suitability:** **Maximum.** Exceptional for validating SENTINEL AI's lateral movement correlation and authentication anomaly tools.
- **Supervised Fine-Tuning:** Unsuitable for direct end-to-end LLM fine-tuning due to 100 GB size, but ideal for generating few-shot incident investigation scenarios.
- **Evaluation:** Gold-standard benchmark for testing whether SENTINEL AI can track adversary pivot hops starting from an initial breach endpoint.

## 4. RESOURCE 4: HUGGING FACE HDFS_v1 (`logfit-project/HDFS_v1`)

### 4.1 Dataset Name & Source
- **Name:** `logfit-project/HDFS_v1`
- **Source:** Hugging Face Datasets repository maintained by the LogFiT project (Log Anomaly Detection using Fine-Tuned Language Models).
- **Upstream Authors:** Wei Xu, Ling Huang, Armando Fox, David Patterson, Michael Jordan (SOSP 2009: *"Detecting Large-Scale System Problems by Mining Console Logs"*).
- **URL:** `https://huggingface.co/datasets/logfit-project/HDFS_v1`

### 4.2 Description
Console logs collected from a private cloud deployment running Hadoop Distributed File System (HDFS) under benchmark MapReduce workloads. Log messages track distributed block lifecycles (`PacketResponder`, `FSNamesystem.addStoredBlock`, `BlockManager`, replica deletions, connection timeouts). Each log line is tied to a specific distributed storage block identifier (`blk_<id>`), with ground-truth binary anomaly flags assigned through rule-based verification.

### 4.3 File Formats & Scale
- **File Formats:** Apache Parquet files split into 5 shards (`data/train-00000-of-00005.parquet` through `00004-of-00005.parquet`).
- **Total Records:** 11,175,629 log lines (spanning 575,061 unique storage blocks).
- **Time Span:** 38.7 hours of continuous distributed cluster operations.

### 4.4 Available Columns & Features
- `date`: 6-digit date stamp (`YYMMDD`, e.g. `081109`).
- `time`: 6-digit timestamp (`HHMMSS`, e.g. `203615`).
- `pid`: Process identifier of the Java daemon thread (e.g. `148`, `222`, `35`).
- `level`: Log level token (`INFO`, `WARN`, `ERROR`).
- `component`: Daemon subsystem emitting the event (e.g. `dfs.DataNode$PacketResponder`, `dfs.FSNamesystem`).
- `content`: Unstructured text message body (e.g. `PacketResponder 1 for block blk_38865049064139660 terminating`).
- `block_id`: Extracted storage block identifier string (`blk_<id>`).
- `anomaly`: Ground truth binary label (`0` = normal block operations, `1` = anomalous block execution).

### 4.5 Class Distribution & Data Quality
- **Block-Level Distribution:** 575,061 total blocks:
  - Normal Blocks: 558,223 (~97.1%)
  - Anomalous Blocks: 16,838 (~2.9%)
- **Data Quality:** Extremely clean; standardized log templates and deterministic timestamp formats.
- **Label Granularity:** Labels are assigned at the block level rather than individual line level; a block is labeled anomalous if an unexpected sequence or failure occurred during its lifecycle.

### 4.6 Cybersecurity Value & SENTINEL AI Suitability
- **RAG Suitability:** Moderate. Useful for understanding distributed infrastructure degradation and data exfiltration through irregular block movements.
- **Structured Analysis Suitability:** **Very High.** Provides structured template mining and distributed block anomaly detection for SENTINEL AI's system log analysis tool.
- **Supervised Fine-Tuning:** Suitable for fine-tuning compact language models or token classification heads to detect log anomalies directly from text.
- **Evaluation:** Robust test suite for checking whether SENTINEL AI correctly pinpoints failed block replicas, timeouts, and anomalous distributed server behavior.

## 5. RESOURCE 5: GITHUB REPOSITORY `logpai/loghub`

### 5.1 Repository Overview & Source
- **Repository:** `logpai/loghub`
- **Maintainer:** LogPAI Research Group (The Chinese University of Hong Kong / Jieming Zhu, Shilin He, Pinjia He, Michael R. Lyu).
- **Publication:** IEEE ISSRE 2023 (*"Loghub: A Large Collection of System Log Datasets for AI-driven Log Analytics"*).
- **License:** MIT License.
- **URL:** `https://github.com/logpai/loghub`

### 5.2 Repository Content & Structure
The repository is an authoritative, freely accessible collection of system logs from real-world production and laboratory environments across five primary domains:
- **Distributed Systems:** HDFS (v1, v2, v3), Hadoop MapReduce (394k lines), Spark (33M lines), ZooKeeper (74k lines), OpenStack (207k lines).
- **Supercomputers:** Blue Gene/L (BGL, 4.7M lines), High Performance Cluster (HPC, 433k lines), Thunderbird (211M lines).
- **Operating Systems:** Windows Event Log (114M lines), Linux Syslog (25k lines), Mac OS (117k lines).
- **Mobile Systems:** Android (v1, v2, 31M lines), HealthApp (253k lines).
- **Server Applications:** OpenSSH (655k lines), Apache Web Server (56k lines), Proxifier (21k lines).

### 5.3 Code, Dependencies & Tooling Ecosystem
- **Included Code:** The repository hosts curated log samples (`<System>_2k.log`), structured parsed representations (`<System>_2k.log_structured.csv`), extracted log event templates (`<System>_2k.log_templates.csv`), and download scripts.
- **Associated Toolkits (LogPAI Suite):**
  - `logparser`: Implementations of 14 log parsing algorithms (Drain, Spell, AEL, LenMa, IPLoM, POP).
  - `loglizer`: Machine learning toolkit for log-based anomaly detection (PCA, Invariant Mining, Isolation Forest, LogClustering).
  - `Drain3`: Streaming log template miner.
- **Dependencies:** Python 3, `pandas`, `numpy`, `scipy`, `scikit-learn`, `regex`.
- **Pretrained Models:** The repository itself does NOT store opaque model weights; instead, it supplies reproducible algorithmic parsers and ground-truth templates that eliminate the need for untrusted external binary execution.

### 5.4 Compatibility with SENTINEL AI Architecture
- **Compatibility:** **100% Compatible.**
- The raw formats in Loghub (RFC 5424 Syslog, OpenSSH, Linux PAM, Windows Security Event logs) match our existing `FileIngestService` and `NormalizerService` pipelines.
- OpenSSH and Linux samples provide immediate ground-truth templates for credential attacks, failed logins, invalid user probing, and daemon failures.

## 7. CONCLUSION & NEXT STEPS

Each of the five resources provides unique, non-overlapping capabilities:
- **Network Layer:** CIC-IDS2017 supplies volumetric and packet-level intrusion metrics.
- **User / Email Layer:** Phishing dataset provides social engineering and domain spoofing patterns.
- **Enterprise Endpoint / AD Layer:** LANL cyber1 provides massive multi-source authentication and Red Team pivot trajectories.
- **Distributed System Layer:** HDFS_v1 models distributed cluster degradation and block failures.
- **OS / Daemon Layer:** Loghub supplies standardized templates for Linux, Windows, and OpenSSH attacks.

These resources will be operationalized through `docs/DATASET_USAGE_STRATEGY.md`.
